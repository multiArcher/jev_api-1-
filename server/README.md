# 外部报文决策服务

本地启动默认只接受 `params.platCode=1010` 的任务。需要控制其他艇时，使用 `--platform-id 1001` 或设置 `PLATFORM_ID=1001`；优先级为命令行参数、环境变量、默认1010。态势仍接收其他艇和目标的信息。代码修改在下次启动时生效，已运行进程不会自动更新。

Kev已接入静态避障：本艇以外、实际速度绝对值不超过0.1节的目标均参与检查，包括未知类型和其他静止船艇。障碍物禁入半径默认80米，加上11.6×3.4米艇体的外接圆半径约6.04米，艇体中心有效避碰半径约86.04米；定位参考点暂按艇体中心处理。可用 `--static-obstacle-radius-m` / `STATIC_OBSTACLE_RADIUS_M`、`--vessel-length-m` / `VESSEL_LENGTH_M`、`--vessel-width-m` / `VESSEL_WIDTH_M` 配置，额外余量用 `--static-obstacle-margin-m` / `STATIC_OBSTACLE_MARGIN_M`（默认0）。内部路径再留10米跟踪余量，这不是扩大航点到达半径。

态势按单目标增量更新，控制工作线程接收目标快照和本地接收年龄。停止探测的静态目标保留最后位置，避免把离开探测范围当作障碍物消失；协议没有删除通知，仿真清场后需要重启服务清理历史目标，或由后续明确的删除协议更新。静态规划使用同一首航点坐标系，通过可见路径生成内部引导点，Kev从满足整段运动与制动距离检查的速度/航向候选中选择；绕开后优先向前汇入原航段，再沿线前进。航点被占据时在原100米到达圈内寻找安全通过位置，不修改任务航点和完成数量；无可用路径或候选时返回 `STATIC_OBSTACLE_BLOCKED` 并下发零速。进展监督跟踪当前引导目标，正常绕行允许暂时远离原航点。

静态避障优先保持原航速和目标方向：远处障碍物不再立即触发斜向绕行，先在本艇至航点的直线上设置接近段，再接上绕行路径。开始绕行的位置依据当前及计划航速、两种速度响应下的预测与制动距离、转向能力和两个控制周期的余量确定，不使用固定的“越近越好”距离；高速或转向较慢时需要更早避让。接近段只保留最贴近目标方向的安全航向，避免模型提前偏航。进入实际绕行阶段后，速度上限设为正常速度阶段上限的一半（例如50节→25节、10节→5节），远处直航接近阶段不减半，绕过后恢复正常速度规划。上限基于正常规划值计算，不随每轮实际速度反复减半；支持25节等非固定档位。候选优先采用半速上限内通过检查的最高速度，仍不安全时继续降档，并记录 `static_safety_fallback`。存在相关静态目标时，绕行和返回原目标方向不再触发额外的航向修正限速，航点限速、进圈／急转准备、恢复状态及发送前避碰复核仍保留。

可复现直航接近与绕行测试：`PYTHONPATH=jev_api:. python3 -m server.experiments.static_avoidance --mock`。不加 `--mock` 时使用本机真实 Kev 服务，可通过 `--kev-endpoint` 指定独立测试端口；此测试不向现场发送控制报文。JSON 输出首次变向距离、最低指令航速及独立积分得到的最小净空。

Kev在控制周期读取到有效本艇态势时，独立记录 `static obstacle actual distance`：本艇到障碍物中心距离不超过125米时才记录距离明细，超过125米结束本次监测并输出 `static obstacle actual summary`，任务结束也汇总未结束的接近过程。日志包括任务/平台/障碍物编号、当前中心距离 `center_distance_m`、相邻采样连线最短距离 `segment_min_distance_m`、安全距离 `safe_distance_m`、安全净距 `clearance_m` 和目标接收年龄。净距不大于0时为WARNING，否则INFO；汇总给出最小距离、最小净距和不安全采样数。这是实际态势采样统计，与候选动作的预测净距不同；连线只在间隔不超过 `situation_max_age` 且障碍物坐标未变化时使用，并标记 `interpolated`，不能替代连续真实轨迹。距离明细和汇总仅写入 `server/logs/static-obstacle-distance-{平台编号}-{任务接收端口}.log`，不输出到终端；每次服务启动覆盖该文件，同一进程的不同任务继续追加。按船艇和接收端口区分文件，避免多船进程相互覆盖。其他控制与异常日志仍输出到终端。

每次控制发送（含旧指令续发）都会依据最新态势复核；出现新的碰撞风险时暂发零速，等待新决策。日志记录静态引导变化和被拦截的控制。静态候选检查同时使用当前模拟速度响应与1.46m/s²加速、1.75m/s²制动边界，加上预测终点后的制动路径，至少预测4秒；转向仍沿用配置的角速度近似，尚未加入真实角加速度和侧滑。Jev/Julia后端未接入这些避障功能。

动态避障已接入 Kev，相关独立模块与适配器位于 `navigation/dynamic_avoidance/`。静态目标仍使用原有规划、接近时半速和轨迹检查；运动目标独立做动态预测，不把静态目标放入动态长时预测。原候选全安全时不改变原输入，有动态风险时才允许调整方向或进一步减速，新增动作仍通过原静态检查且不突破静态半速上限。静态守卫与动态守卫分别记录风险；动态检查也覆盖零速及旧指令续发。无共同安全动作时暂发零速等待，零速不代表安全保证。测试方法、参数及预测限制见 [动态避障说明](navigation/dynamic_avoidance/README.md)。代码修改需要重启报文服务后才生效。

动态预警和动作窗口分别为60秒与10秒：远期风险只写预警日志和决策记录，不进入模型提示词，不触发变向、降速或控制拦截。候选筛选、主动避让及发送前复核统一使用10秒动作窗口，仍覆盖必要的变速、转向和完整制动尾段，因此并非固定等到碰撞前10秒才避让。可通过独立动态配置的 `warning_horizon_s`、`action_horizon_s` 调整；静态避障触发及半速规则不变。

静态绕障、动态避让后的回线功能默认启用，单独实现于 `navigation/route_rejoin.py`。航线固定为上一航点至当前航点，首段以任务首次本艇位置为起点。前方安全汇入点不能被直达航点快捷跳过；回线不额外固定限速，继续遵守现有静动态避碰和速度阶段。横向10米、航向5度内连续3轮完成回线，随后持续沿线引导；原航点100米到达规则不变。配置、状态与离线闭环入口见 [回线说明](navigation/ROUTE_REJOIN.md)。仅需重启报文决策服务，无需重启 Kev 模型。

先启动 Kev-4B 推理服务（单独终端保持运行）：

```bash
.venv-kev/bin/python server/local_models/serve_kev.py --device cuda
```

再启动报文服务，默认使用 Kev-4B：

```bash
python3 server/decision_service.py --multicast-interface 192.168.3.202

python3 server/decision_service.py --multicast-interface 192.168.3.202 --platform-id 1010
```

Kev 通过独立接口 `http://127.0.0.1:18028/v1/systemone` 推理，速度由 `policies/kev_policy.py` 的 `KEV_SPEEDS_KNOTS` 设置为10、20、30、40、50节，每个可用档位配合16个局部可达航向；速度阶段根据下一航点转角、距离和限速确定。服务接收 `0x0660` 的 `trackingMode` 任务、`0x0666` 停止请求和 `0x0060` 态势，按 `params.platCode == platformId` 选本艇，输出 `0x0662` 控制报文。可恢复错误连续达到3次才返回 `0x0664` 失败状态；任务/停止请求支持最多10片的协议分包重组。

Jev 保留原有64个速度/航向候选及本机密钥配置，可显式切换：

```bash
python3 server/decision_service.py --backend jev --multicast-interface 192.168.3.202
```

也可通过 `POLICY_BACKEND=kev/jev/julia` 选择后端；命令行参数优先。策略由 `policies/factory.py` 创建，报文接收、态势缓存、控制与状态上报共用原有流程。启动日志显示实际后端。Compose 同样默认 Kev，须单独运行其推理服务；使用 Jev 时在 `.env` 中设置 `POLICY_BACKEND=jev` 并填写 `JEV_API_KEY`。

启动时自动读取脚本同目录的 `decision_service.local.json`，其中可保存
`JEV_API_KEY` 和 `JEV_ENDPOINT`，无需每次执行 `export`。Kev 的实际初始方向也可保存为
`INITIAL_COURSE_DEG`（0到360度，不含360），仅作为静止且态势未提供 `targetCourse` 时的备用方向；有效态势航向始终优先，0度也有效。该文件已加入 Git 忽略规则，
包含密钥时应仅在本机保存，不要复制进镜像。环境变量优先于本机配置；
本机配置还支持 `MAX_CONSECUTIVE_ERRORS` 和 `COMMAND_HOLD_TIMEOUT`。模型、地址也可用 `--model`、`--endpoint` 参数覆盖，命令行参数优先。
Jev 默认接口地址为 `https://api.jevcn.cn/v1/systemone`；Kev 使用独立的
`--kev-endpoint` / `KEV_ENDPOINT`，无需 Jev 密钥。

适配约定：

- 默认态势速度、航路点 `routeSpeed` 和控制输出均按节处理；若外部三者均为 m/s，使用 `--speed-unit mps`。协议文档未明确三者物理单位，接实艇前需核对。Jev 内部航路点上限统一为 m/s。
- 航向为北起顺时针绝对角度。Jev 最大候选速度默认 50 节（`--max-speed-knots`）；Kev 使用10、20、30、40、50节五档速度（`--max-speed-knots` 可进一步限制可用档位），转向角速度参数为 `--max-turn-rate-deg-s`，默认45度/秒。1秒周期对应当前方向±45度的候选范围，0.2秒周期对应±9度。该参数用于候选生成和运动预测，须按实际船舶配置。Kev 每轮读取最新态势中的位置、速度与 `targetCourse`，速度为0时也保留有效航向；只有静止且未提供航向时，才需要 `--initial-course-deg` 作为备用。
- `planWaypointList` 中每一项都是必须访问的目标，支持只有1个航点；当前位置取自态势，不把列表首项当成起点。`currentRoute` 是已完成航点数量：0从列表第1点开始，1从第2点开始。可选 `next_waypoint_index` 为从0开始的明确目标索引。`routeRadius` 表示航路点转弯半径，目前保留原报文字段但不参与计算或任务校验。所有航点的到达半径暂统一为100米，由 `policies/waypoint_radius.py` 的 `DEFAULT_ARRIVAL_RADIUS_M` 管理，后续按无人艇实测数据设置；列表最后一项就是终点。
- 速度阶段由 `policies/speed_profile.py` 管理：远离航点且航向误差不超过15度时使用可用最高档（默认50节）；接近航点时根据下一段转角、航点限速和减速提前量限制速度。仍处于已访问航点圈内时继续遵守其限速，大角度修正和恢复阶段允许减速。下一点仅用于提前规划，不跳过当前航点。
- 决策内部以首个航路点为固定原点，使用东/北米制坐标，候选预测和到达判定采用同一坐标系；外部任务、态势和控制报文字段及单位保持原约定。Kev模型只接收内部坐标和目标相对位置。
- Kev进展监督默认比较最近5次决策观测：目标距离未改善且航向误差没有下降时进入低速恢复，仅提供10节与16航向组合。掉头时允许暂时远离，只要航向在改善。恢复中对齐到30度内且距离减小后返回正常；连续20轮无改善则下发零速并以 `NAVIGATION_NO_PROGRESS` 报告失败。换航点、新任务会清空相应历史。
- `--control-interval` 默认1秒，也是候选动作预测时长。每个任务使用独立模型工作线程，控制发送不被推理阻塞；同一任务最多一个请求在途。航点改变、到达终点或收到停止请求后，不采用之前航点的滞后结果。
- 接收任务后，控制台以 INFO 打印重组后的完整 JSON（含全部航点和原有字段，中文直接显示），并保留任务摘要（ID、平台、航点数量、起始进度）、停止请求、任务完成和错误信息。完整任务在平台过滤和字段校验前打印，便于排查被忽略或校验失败的报文。每次成功发送动力控制 `0x0662` 后，以 INFO 打印目标地址、任务ID、平台编号、编码后的航速/航向、模式（`new`新决策、`hold`续发、`stop`停车）及完整十六进制报文；这些发送日志逐条打印。态势保持逐包实时接收与缓存，接收日志在所有平台和接收入口之间共享5秒限频；其他每周期控制与推理明细保持 DEBUG。
- `--status-interval` 默认 1 秒。执行中状态由独立定时线程按单调时钟上报，不受模型请求耗时影响。
- 启动时自动加入态势组播 `239.255.0.10:18010`；加入或接收出现 socket 错误后，每隔 3 秒自动重试。多网卡环境可通过 `--multicast-interface` 或 `MULTICAST_INTERFACE` 指定本机网卡 IPv4。
- 执行中 `0x0664.params` 返回 `nextWaypointIndex`、`nextWaypoint`、`remainingWaypointNum`、`remainingDistanceM`、`estimatedRemainingTimeS` 和 `completionRate`；其中目标索引从0开始，`currentRoute` 返回已完成数量。首段距离包含首次有效态势的位置到第一个待访问点。距离单位为米，时间单位为秒，`completionRate` 为0到100的数值百分比；必要速度为0时预计时间为 `null`。
- 每个容器通过 `PLATFORM_ID` 只接收一个平台的任务。同一 `platCode` 每收到一个校验通过的新任务，就立即覆盖该艇尚未结束的旧任务；`simId/id` 和参数完全相同也会覆盖，不按重复报文忽略。新任务从自己报文中的 `currentRoute` 开始，使用当前态势，不继承旧任务的航点进度或模型历史。不同艇独立处理；校验失败的新任务不会撤销正在执行的任务。
- 覆盖时先撤销旧任务的输出权，旧任务立即退出控制循环，其滞后的模型结果、周期状态、错误处理和停车指令都不能影响新任务。不同 `simId+id` 的旧任务返回 `status=3`，`params.phase=superseded`、`errorCode=TASK_SUPERSEDED`，原因说明已被新任务覆盖，并附 `replacedByTaskId/replacedBySimId`；同 `simId+id` 不发送旧任务终态，避免覆盖行为树缓存中的新状态。新任务正常上报 `status=1`。同 ID 的后续停止报文作用于当前新实例。
- 旧在途模型请求不保证能强制中断，但返回结果会被丢弃；新任务不等待旧控制线程或 HTTP 请求结束。Kev 的 HTTP opener 和导航状态按线程隔离，客户端不再用旧请求的互斥锁阻塞新请求；模型服务繁忙时仍可能排队。此处没有恢复任务链或等待前序完成的队列。
- 收到 `0x0666` 后停止常规航迹动作，持续向动力系统下发目标航速0；组播本艇实际航速不高于 `STOP_SPEED_THRESHOLD` 后，回复 `status=2` 的停车完成状态。
- 全部航点到达后自动进入 `finishing` 停车阶段，持续下发0速；停车确认后才报告 `status=2`。到达终点后即使因惯性移出到达圈，也保持停车阶段。`completionRate=100` 表示航点已访问完，停车尚未确认时仍是执行中 `status=1`。
- `SITUATION_MAX_AGE` 限制可用于决策的本艇态势新鲜度，默认2.5秒；命令行服务 `JEV_TIMEOUT` 默认30秒，`KEV_TIMEOUT` 默认120秒。
- `--max-consecutive-errors` / `MAX_CONSECUTIVE_ERRORS` 默认3。模型请求超时、断连、HTTP 408/429/5xx、控制发送失败以及连续控制周期缺少新鲜态势均会记录错误；恢复成功后清零。连续3次才发送零速并报告 `status=3`。非法任务字段、无效模型选项、鉴权错误等不可恢复错误直接失败。
- `--command-hold-timeout` / `COMMAND_HOLD_TIMEOUT` 默认5秒，以最近有效决策的时间计算。重试或等待期间按控制周期续发上一有效指令；超过时限暂发0速并继续等待/重试，尚无有效指令时不会生成替代动作。耗时超过此时限的模型结果会被丢弃并记录超时，不能把旧态势生成的动作当作新决策下发。HTTP请求仍由后端自己的超时参数结束；5秒保持时限不代表取消在途HTTP请求。
- 失败 `description` 包含阶段、平台、航点、连续次数和原始原因，并区分“已发送停车指令”与“已确认停车”。`params` 同时提供 `phase`、`errorCode`、`errorStage`、`errorType`、`lastError`、`consecutiveErrors`、`maxConsecutiveErrors`、`stopCommandSent`、`stopConfirmed`；鉴权密钥不写入原因文本。最终状态遇到socket发送错误时会重试，状态通道错误不混记为模型错误。
- `--max-cycles=0` 持续运行到路线完成或停止请求；正数是调试用的有效控制次数上限，达到上限也会先停车确认再结束。航点、终点停车、重试和状态由公共控制流程处理，Kev/Jev/Julia只负责动作选择。
